# Post-mortem INC-2025-0120: CrashLoopBackOff on startup due to a missing environment variable / secret

| Field | Value |
|---|---|
| Date | 2025-03-27 |
| Service | `orders-worker` |
| Environment | production |
| Severity | SEV2 |
| Duration | 26 minutes |

## Summary
Order processing paused for 26 minutes; backlog of 8k messages, no data loss. Trigger: Secret key rename not coordinated with the Deployment.

## Detection
Deployment rollout stuck alert.

## Timeline (UTC)
- 16:00 Secret rotation renames key to DB_URL.
- 16:04 New orders-worker pods CrashLoopBackOff with KeyError: 'DATABASE_URL'.
- 16:20 Rollout undone; old pods resume.

## Error Signatures Observed
```text
Traceback (most recent call last):
  File "/srv/app/config.py", line 14, in load_config
    database_url=os.environ["DATABASE_URL"],
KeyError: 'DATABASE_URL'
Warning  BackOff  kubelet  Back-off restarting failed container orders-worker
```

## Root Cause Analysis
**Trigger:** Secret key rename not coordinated with the Deployment.

The new Deployment referenced a Secret key renamed during a secret rotation (`DATABASE_URL` -> `DB_URL`).
The app fails fast at startup. If the referenced Secret itself doesn't exist, the pod instead shows
`CreateContainerConfigError`.

## Resolution
Rollback, then aligned key names and added CI check.

| # | Action | Status |
|---|---|---|

## Lessons Learned
Read `--previous` logs first for CrashLoopBackOff; the answer is usually the last 10 lines.
