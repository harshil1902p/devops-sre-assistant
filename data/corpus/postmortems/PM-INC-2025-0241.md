# Post-mortem INC-2025-0241: 502 Bad Gateway during deploys - upstream connection refused

| Field | Value |
|---|---|
| Date | 2025-07-01 |
| Service | `api-gateway` |
| Environment | production |
| Severity | SEV3 |
| Duration | 8 minutes |

## Summary
2% of order submissions failed with 502 during each deploy. Trigger: No preStop delay; endpoints removed after pods stopped listening.

## Detection
Deploy-correlated 5xx dashboard.

## Timeline (UTC)
- 10:00 Rolling deploy of orders-api.
- 10:02 502 burst with connection refused.
- 10:08 Rollout completes; errors stop.

## Error Signatures Observed
```text
2025/07/01 10:02:13 [error] 29#29: *1201 connect() failed (111: Connection refused) while connecting to upstream, upstream: "http://10.0.5.33:8080/v1/orders"
10.0.1.9 - - [01/Jul/2025:10:02:13 +0000] "POST /v1/orders HTTP/1.1" 502 150
```

## Root Cause Analysis
**Trigger:** No preStop delay; endpoints removed after pods stopped listening.

Pods were removed from endpoints after they had already stopped accepting connections (no preStop
delay), and new pods were marked Ready before the app listened (readiness probe hitting a static path).

## Resolution
preStop sleep and graceful SIGTERM handling.

## Action Items
| # | Action | Status |
|---|---|---|
| 1 | Default preStop in the Helm chart (owner: platform). | Open |

## Lessons Learned
Zero-downtime deploys require coordinated readiness and graceful shutdown.
