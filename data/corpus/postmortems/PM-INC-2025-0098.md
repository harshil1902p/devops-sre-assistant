# Post-mortem INC-2025-0098: Disk full on database volume - 'No space left on device'

| Field | Value |
|---|---|
| Date | 2025-03-02 |
| Service | `orders-db` |
| Environment | production |
| Severity | SEV1 |
| Duration | 64 minutes |

## Summary
Order placement unavailable for 64 minutes. Trigger: Decommissioned CDC connector left an inactive replication slot retaining WAL.

## Detection
orders-api 5xx alert; Postgres pod in CrashLoopBackOff.

## Timeline (UTC)
- 02:11 Disk reaches 100%; Postgres PANIC on WAL write.
- 02:30 On-call finds pg_wal at 78 GiB and an inactive CDC replication slot.
- 02:52 PVC expanded to 200Gi; slot dropped; Postgres restarts.
- 03:15 Service recovered.

## Error Signatures Observed
```text
ERROR:  could not extend file "base/16384/24576": No space left on device
HINT:  Check free disk space.
PANIC:  could not write to file "pg_wal/xlogtemp.212": No space left on device
LOG:  database system is shut down
```

## Root Cause Analysis
**Trigger:** Decommissioned CDC connector left an inactive replication slot retaining WAL.

WAL files accumulated because an inactive replication slot (from a decommissioned read replica / CDC
connector) prevented WAL recycling, filling the 100 GiB persistent volume.

## Resolution
Expanded volume, dropped slot, configured max_slot_wal_keep_size.

## Action Items
| # | Action | Status |
|---|---|---|
| 1 | Disk usage alert at 80% (owner: SRE). | Open |
| 2 | Decommission checklist must include replication slots (owner: data platform). | Open |

## Lessons Learned
Inactive replication slots silently retain WAL until the disk fills.
