# Post-mortem INC-2025-0193: Java heap space OutOfMemoryError in reporting-service

| Field | Value |
|---|---|
| Date | 2025-05-20 |
| Service | `reporting-service` |
| Environment | production |
| Severity | SEV3 |
| Duration | 300 minutes |

## Summary
Month-end exports failed for 5 hours for large clients. Trigger: Default JVM heap sizing plus in-memory export.

## Detection
Customer support tickets.

## Timeline (UTC)
- 09:00 Month-end export runs; OutOfMemoryError: Java heap space.
- 12:30 Heap found capped at 512 MB (25% of 2 GiB).
- 14:00 MaxRAMPercentage=75 deployed; exports succeed.

## Error Signatures Observed
```text
Exception in thread "report-exec-3" java.lang.OutOfMemoryError: Java heap space
    at java.base/java.util.Arrays.copyOf(Arrays.java:3537)
    at com.contoso.reporting.ExportService.buildCsv(ExportService.java:88)
```

## Root Cause Analysis
**Trigger:** Default JVM heap sizing plus in-memory export.

The JVM max heap is smaller than what the export needs because it loads the whole result set into memory.
The container limit (2Gi) was not the constraint; the heap size (default 25% of RAM) was.

## Resolution
Heap flag, then streaming export.

## Action Items
| # | Action | Status |
|---|---|---|
| 1 | Streaming CSV export (owner: reporting). | Open |

## Lessons Learned
Container memory limit != JVM heap; size the heap explicitly.
