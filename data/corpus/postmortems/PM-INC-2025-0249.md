# Post-mortem INC-2025-0249: ImagePullBackOff - AKS cannot pull image from Azure Container Registry

| Field | Value |
|---|---|
| Date | 2025-07-08 |
| Service | `orders-api` |
| Environment | staging |
| Severity | SEV3 |
| Duration | 55 minutes |

## Summary
Staging deployments blocked for 55 minutes. Trigger: Missing AcrPull role assignment for the new kubelet identity.

## Detection
CD pipeline timeout.

## Timeline (UTC)
- 10:00 Staging cluster recreated from IaC without AcrPull assignment.
- 10:15 Deploy fails with 401 Unauthorized on image pull.
- 10:55 ACR attached; pods start.

## Error Signatures Observed
```text
Warning  Failed     kubelet  Failed to pull image "contosoacr.azurecr.io/orders-api:1.42.0": rpc error: code = Unknown desc = failed to authorize: failed to fetch anonymous token: unexpected status: 401 Unauthorized
Warning  Failed     kubelet  Error: ErrImagePull
Normal   BackOff    kubelet  Back-off pulling image "contosoacr.azurecr.io/orders-api:1.42.0"
```

## Root Cause Analysis
**Trigger:** Missing AcrPull role assignment for the new kubelet identity.

Either the tag doesn't exist (`manifest unknown`) or the AKS kubelet identity lost `AcrPull` on the
registry (`401 Unauthorized`) after the cluster was recreated.

## Resolution
Added role assignment to Bicep.

| # | Action | Status |
|---|---|---|
| 1 | Add `az aks check-acr` to post-provision smoke tests (owner: platform). | Open |

## Lessons Learned
Identity and role assignments are part of the infrastructure; codify them.
