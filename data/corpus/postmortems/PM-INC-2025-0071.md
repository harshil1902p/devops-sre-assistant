# Post-mortem INC-2025-0071: Cascading restarts because the liveness probe checks downstream dependencies

| Field | Value |
|---|---|
| Date | 2025-02-11 |
| Service | `auth-service` |
| Environment | production |
| Severity | SEV1 |
| Duration | 12 minutes |

## Summary
Complete login outage for 12 minutes triggered by a 30-second Redis failover. Trigger: Liveness probe included dependency checks.

## Detection
Availability SLO alert.

## Timeline (UTC)
- 07:30 Azure Cache for Redis planned failover (~30 s).
- 07:31 All auth-service pods fail liveness (503) and are restarted simultaneously.
- 07:42 Pods back after cold start and DB connection storms.

## Error Signatures Observed
```text
Warning  Unhealthy  kubelet  Liveness probe failed: HTTP probe failed with statuscode: 503
Normal   Killing    kubelet  Container auth-service failed liveness probe, will be restarted
```

## Root Cause Analysis
**Trigger:** Liveness probe included dependency checks.

The liveness probe called `/health`, which checked Postgres and Redis. A 30-second Redis failover made
every pod fail liveness; kubelet killed them all, turning a small blip into a full outage.

## Resolution
Split /healthz (liveness) and /readyz (readiness).

## Action Items
| # | Action | Status |
|---|---|---|
| 1 | Probe guidelines in the platform handbook (owner: SRE). | Open |

## Lessons Learned
Liveness probes must never depend on other services.
