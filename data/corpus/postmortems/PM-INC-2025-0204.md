# Post-mortem INC-2025-0204: Intermittent DNS resolution failures - Temporary failure in name resolution

| Field | Value |
|---|---|
| Date | 2025-05-29 |
| Service | `payments-api` |
| Environment | production |
| Severity | SEV3 |
| Duration | 50 minutes |

## Summary
1.5% of payment provider calls failed. Trigger: DNS query amplification from ndots:5 at peak traffic.

## Detection
Payment provider error-rate alert.

## Timeline (UTC)
- 12:00 Traffic peak; EAI_AGAIN errors.
- 12:30 CoreDNS CPU saturated identified.
- 12:50 CoreDNS scaled to 6; ndots reduced.

## Error Signatures Observed
```text
httpx.ConnectError: [Errno -3] Temporary failure in name resolution
socket.gaierror: [Errno -3] Temporary failure in name resolution
```

## Root Cause Analysis
**Trigger:** DNS query amplification from ndots:5 at peak traffic.

CoreDNS was overloaded: `ndots:5` made every external lookup try 4 cluster search domains first,
multiplying DNS queries, and CoreDNS had only 2 replicas.

## Resolution
Scaled CoreDNS, ndots:2, NodeLocal DNSCache.

## Action Items
| # | Action | Status |
|---|---|---|
| 1 | NodeLocal DNSCache in all clusters (owner: platform). | Open |

## Lessons Learned
DNS is a shared dependency; monitor it like one.
