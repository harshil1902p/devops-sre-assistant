# Post-mortem INC-2025-0164: Container OOMKilled (exit code 137) from an unbounded in-memory cache

| Field | Value |
|---|---|
| Date | 2025-05-02 |
| Service | `auth-service` |
| Environment | production |
| Severity | SEV2 |
| Duration | 210 minutes |

## Summary
auth-service pods restarted every ~25 minutes for 3.5 hours; 0.4% of logins failed with connection resets. Trigger: Unbounded dictionary cache keyed by unique session tokens.

## Detection
Alert on pod restart count > 3 in 30 minutes.

## Timeline (UTC)
- 09:30 Release v2.33 adds an in-process cache of user profiles keyed by session token.
- 10:05 First OOMKilled restart; no errors in application logs.
- 11:10 On-call notices memory saw-tooth pattern in Grafana and exit code 137 in `kubectl describe`.
- 12:20 tracemalloc in staging points to the profile cache dict growing without bound.
- 13:00 Hotfix replaces dict with TTLCache(maxsize=10000, ttl=300); restarts stop.

## Error Signatures Observed
```text
{"level": "INFO", "logger": "auth.runtime", "msg": "runtime stats", "rss_mb": 115.7}
{"level": "INFO", "logger": "auth.runtime", "msg": "runtime stats", "rss_mb": 175.8}
{"level": "INFO", "logger": "auth.runtime", "msg": "runtime stats", "rss_mb": 223.8}
{"level": "INFO", "logger": "auth.api", "msg": "starting auth-service (env=production)"}
# kubectl describe pod: Last State: Terminated  Reason: OOMKilled  Exit Code: 137
```

## Root Cause Analysis
**Trigger:** Unbounded dictionary cache keyed by unique session tokens.

The container exceeded its memory limit (256Mi) and the kernel OOM killer sent SIGKILL (128 + 9 = exit 137).
The process memory grew because an in-process cache had no size bound or TTL, so every unique key stayed
in memory forever. Restarting hides the leak until memory fills again.

## Resolution
Bounded TTL cache, memory alert at 85% of limit, limit raised to 512Mi.
