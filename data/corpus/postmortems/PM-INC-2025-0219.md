# Post-mortem INC-2025-0219: 504 Gateway Timeout from api-gateway - upstream timed out

| Field | Value |
|---|---|
| Date | 2025-06-12 |
| Service | `api-gateway` |
| Environment | production |
| Severity | SEV2 |
| Duration | 75 minutes |

## Summary
Annual report downloads failed with 504 for 75 minutes. Trigger: Missing index after data growth made the report query take 90 s.

## Detection
Gateway 5xx alert.

## Timeline (UTC)
- 13:30 Reports table grows past an index threshold; query plan changes.
- 13:44 504s from the gateway with `upstream timed out`.
- 14:45 Index added; latency back to 3 s.

## Error Signatures Observed
```text
2025/06/12 13:44:02 [error] 31#31: *88213 upstream timed out (110: Connection timed out) while reading response header from upstream, client: 10.0.1.4, server: api.contoso.com, request: "GET /v1/reports/annual HTTP/1.1", upstream: "http://10.0.5.21:8080/v1/reports/annual"
10.0.1.4 - - [12/Jun/2025:13:44:02 +0000] "GET /v1/reports/annual HTTP/1.1" 504 160 "-" "Mozilla/5.0"
```

## Root Cause Analysis
**Trigger:** Missing index after data growth made the report query take 90 s.

The upstream took longer than the gateway's `proxy_read_timeout` to start responding. The gateway gave up
and returned 504 while the upstream kept working (wasting resources).

## Resolution
Added index; converted report to async job.

## Action Items
| # | Action | Status |
|---|---|---|
| 1 | Async report generation (owner: reports). | Open |

## Lessons Learned
504 means the upstream is slow; fix the latency, don't just raise timeouts.
