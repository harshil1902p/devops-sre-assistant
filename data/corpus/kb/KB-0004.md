# sqlalchemy.exc.TimeoutError: QueuePool limit of size 5 overflow 10 reached - but Postgres is idle?

**Tags:** connection-pool, database, latency, postgres, sqlalchemy

## Question
Our FastAPI service randomly returns 500s under load with:

```
sqlalchemy.exc.TimeoutError: QueuePool limit of size 5 overflow 10 reached, connection timed out, timeout 30.00
```

Postgres CPU is at 10% and `max_connections` is 100, so the DB is clearly not overloaded. Why does this happen?

## Accepted Answer
The limit in that message is SQLAlchemy's **client-side** pool, not Postgres. All `pool_size + max_overflow`
connections are checked out, so new requests wait `pool_timeout` and give up.

Usual causes:
1. Sessions not closed: use `with Session() as s:` or FastAPI dependencies with `yield`.
2. Long transactions or slow queries holding connections (check `pg_stat_activity`).
3. Pool simply too small for your concurrency: raise `pool_size` (e.g., 20) but keep
   `replicas * (pool_size + max_overflow) < max_connections`.

Also set `statement_timeout` so a single slow query cannot hold a connection forever.

## Comments
> We had a background thread calling `session = Session()` without closing it. Switching to a context manager fixed it.
