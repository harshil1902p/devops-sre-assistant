# Postgres 'FATAL: sorry, too many clients already' after Kubernetes autoscaling

**Tags:** autoscaling, database, max_connections, pgbouncer, postgres

## Question
After enabling HPA on our Django API we started getting
`FATAL: sorry, too many clients already`. Should I just raise max_connections to 1000?

## Accepted Answer
Raising `max_connections` far is risky: each Postgres connection is a process using several MB of RAM
and contention grows. The standard fix is a **connection pooler** (PgBouncer, or the built-in pooler of
managed services such as Azure Database for PostgreSQL Flexible Server) in transaction mode, plus
smaller per-pod pools. Always calculate `replicas x pool size` against the server limit.

## Comments
> Azure Flexible Server has PgBouncer built in; enabling it took 5 minutes.
