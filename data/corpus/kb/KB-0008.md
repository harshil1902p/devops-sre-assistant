# Kubernetes pod restarts with exit code 137 and no error in logs

**Tags:** container, limits, memory, memory-leak, oom, restarts

## Question
Our Python pod restarts every 20-30 minutes. Logs end abruptly with no exception.
`kubectl get pods` shows restarts increasing. What does exit code 137 mean?

## Accepted Answer
137 = 128 + 9 (SIGKILL). In Kubernetes it almost always means the container hit its memory limit and the
kernel OOM killer terminated it (`Reason: OOMKilled` in `kubectl describe pod`). The app can't log because
SIGKILL can't be caught. Check memory over time; a steady climb is a leak (often an unbounded cache).
Use `kubectl logs --previous` to see logs from the killed container.

## Comments
> If Reason is 'Error' with 137 it can also be a liveness probe kill. Check events too.
